# Experiment 002: Prompt Engineering

## Purpose

研究Prompt对LLM输出质量的影响。

## Model

Qwen3-8B（Ollama）

脚本：`llm/prompt/prompt_comparison.py`

## Case 1

Prompt:

```text
解释Transformer
```

Output:

```text
Transformer 是一种革命性的神经网络架构，由 Google 团队于 2017 年提出，主要用于自然语言处理（NLP）任务，如机器翻译、文本生成等。它彻底改变了传统 RNN（循环神经网络）和 CNN（卷积神经网络）的处理方式，核心创新在于注意力机制（Attention Mechanism），能够高效处理长序列数据并并行计算。

1. 背景与传统模型的局限性：RNN 存在长距离依赖、训练效率低、梯度消失/爆炸问题，Transformer 引入注意力机制，完全摒弃循环结构。
2. Transformer 的核心结构：编码器（多头自注意力 + 前馈网络）与解码器（掩码自注意力 + 编码器-解码器注意力 + 前馈网络），各 6 层。
3. 注意力机制：Q、K、V 计算 Attention(Q,K,V) = softmax(QK^T/√d_k)V，多头注意力捕捉不同粒度依赖。
4. 位置编码：正弦/余弦函数生成，保留序列顺序信息。
5. 优势：并行计算、长距离依赖、灵活性。
6. 应用与影响：机器翻译（Google 翻译）、文本生成（GPT、BERT）、图像识别（ViT）等。
7. 总结：动态关注上下文 + 并行计算 + 灵活扩展，成为现代 NLP 基石。
```

Evaluation:

- 完整性：高。覆盖背景、结构、注意力、位置编码、优势、应用全链路，无重大遗漏。
- 准确性：高。QKV 与 softmax 公式、位置编码公式均正确，无事实错误。
- 结构化：清晰但默认"教科书式"。Markdown 分节规整，但术语密集（掩码自注意力、上下文表示、梯度消失），没有面向初学者的铺垫和生活化例子——因为模型不知道"讲给谁听"。

## Case 2

Prompt:

```text
你是一名人工智能领域专家。

请解释Transformer。

要求：
1. 面向AI初学者
2. 使用简单语言
3. 给出实际例子
```

Output:

```text
好的！我用简单语言和例子来解释 Transformer，适合AI初学者理解。

什么是 Transformer？一种处理文本（比如翻译、问答）的神经网络模型，解决了传统模型（如 RNN）处理长句子时速度慢、容易忘记前面内容的缺点。

为什么需要 Transformer？传统模型（如 RNN）像"流水线工人"，只能一次处理一个词，效率低；Transformer 则像"团队协作"，可以同时处理整个句子，更快更准确。

核心：自注意力机制。简单比喻——翻译"猫在桌子上"时，"猫"会注意到"桌子"和"在"的关系，模型自动判断哪些词更重要（"猫"是主语，"桌子"是地点）。实际例子：翻译 "Hello, how are you?" 时同时关注 "Hello"和"how"（问候）、"are"和"you"（动词+主语）的关系，译成"你好，最近好吗？"更自然。

结构（简化版）：输入句子 → 分词 [I, love, cats] → 自注意力 → 位置编码（告诉模型"I"是第一个词）→ 输出翻译"我爱猫。"

实际应用：机器翻译（Google 翻译、DeepL）、问答系统（从上下文找到 "William Shakespeare"）、文本生成（续写 "Once upon a time..."）。

小结对比表：RNN 逐词处理效率低 / Transformer 同时处理整句效率高；RNN 难处理长句子 / Transformer 用自注意力解决。
```

Evaluation:

- 与 Case 1 的区别：**语言风格完全变了**。口语化、大量比喻（"流水线工人 vs 团队协作"）、emoji 分节标题、对比表格，术语几乎消失，数学公式全部省略。
- 完整性：中等。核心概念都在，但位置编码等细节一笔带过，没有公式。
- 准确性：高。简化但不失真，比喻恰当（并行处理 ≈ 团队协作）。
- 结构化：对初学者非常友好——有铺垫、有例子、有总结表。
- 说明：受众（AI初学者）+ 风格（简单语言）+ 例子约束，每一项要求都被模型执行了。

## Case 3

Prompt:

```text
请按照以下结构解释Transformer：

# 1. Transformer解决什么问题

# 2. 核心组成

# 3. Attention机制

# 4. 一个生活中的例子

# 5. 总结
```

Output:

```text
# 1. Transformer解决什么问题
解决序列数据处理的关键挑战：RNN 的长距离依赖（梯度消失/爆炸）与串行低效、CNN 局部特征难以建模全局依赖。Transformer 用自注意力机制 + 位置编码实现全局建模与高效并行。

# 2. 核心组成
编码器与解码器，每部分含多个相同子层：多头自注意力、前馈网络、位置编码、残差连接与层归一化。

# 3. Attention机制
每个位置的词向量与其他位置交互：线性变换得 Q/K/V → QK^T 计算相似度 → softmax 归一化加权求和。多头设计捕捉不同语义层面。

# 4. 一个生活中的例子
翻译"猫在桌子上"→"The cat is on the table"：自注意力让"猫"关注"桌子上"（空间关系）、"在"关联"on"（介词语法）；解码时生成"table"结合前文所有信息保证连贯；位置编码确保词序正确。

# 5. 总结
自注意力 + 位置编码解决传统序列模型局限：全局依赖建模、并行计算、多头灵活性。已是 NLP 基石，推动 BERT、GPT 发展。
```

Evaluation:

- **输出结构完全按 prompt 指定的 5 个标题组织**，逐字遵循，无跑题、无自由发挥的额外章节——结构可控性是三种 prompt 里最高的。
- 完整性：高，信息密度大（每个章节都紧凑无废话）。
- 准确性：高。
- "是否更稳定"：是。这里体现在"结构稳定性"上——章节组织被 prompt 锁定。要注意本次是单次运行，若严格验证可对同一 prompt 多次运行对比（参考 Experiment 003 的方法）。

---

## Conclusion

发现：

1. **模型默认不知道"讲给谁听"**：Zero-shot（Case 1）输出专业完整，但是"教科书式"的，术语密集、无例子，对初学者不友好——输出的风格完全取决于 prompt 里给没给受众信息。
2. **角色 + 受众 + 要求能精确控制风格**（Case 2）：加上"专家身份、面向初学者、简单语言、给例子"后，模型改用比喻、emoji、表格和实例，可读性大幅提升，且要求的三点全部被执行；代价是数学细节被省略。
3. **结构化 prompt 锁定输出组织**（Case 3）：给定章节标题后输出逐字遵循，适合需要固定格式、可解析输出的场景（如批量生成、报告模板）。三个 Case 的核心知识一致，差异主要在**表达方式**而非事实准确性——Prompt 改变的是"怎么讲"，而不是"讲什么"。
